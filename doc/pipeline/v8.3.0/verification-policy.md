# Проверка и ручная приёмка v8.3

Автоматически выполняются только объявленные команды и минимальные наблюдения SQL. Docker не проверяется и не запускается. Сложные DB-сценарии, миграции, деплой и торговые действия — ручные инструкции человеку в согласованной среде.

Optional SQL: не более 5 простых запросов, 15 секунд, максимум 1 MiB вывода. SELECT заканчивается LIMIT 1..200, кроме SELECT 1. Неисполняющий EXPLAIN SELECT разрешён; EXPLAIN ANALYZE, DML/DDL, комментарии, несколько statements и сложные функции запрещены. Это дополнительная проверка, а не замена реальной readonly-роли DB.

Локально в projects/<key>/config.env оператор может задать AI_DB_READONLY_COMMAND и AI_DB_READONLY_CONFIRMED=1. Секреты не передавать в task или Git. Команда принимает SQL из stdin. При отсутствии настроек перенести наблюдение в ручной сценарий; не искать другие DB credentials.

Runner собирает stdout/stderr локально. Независимый Codex в read-only оценивает только автоматические assertions. Каждая должна быть подтверждена конкретными предоставленными данными. Manual scenarios остаются pending; их отсутствие не превращается в ложный automatic fail или pass.

Если автоматических assertions нет, результат только observations_completed, а бизнес-поведение остаётся для ручной приёмки. Для критической задачи ручные сценарии должны явно покрывать критические риски. Успешный startup с 0 tests не равен проверке алгоритма.

После gates сохраняется checkpoint/Draft PR, затем runner останавливается. Acceptance оформляется по реальному сообщению пользователя с проверенным SHA, revision, contract hash, результатами сценариев, признанием deferred expectations и отдельным разрешением test-only.

Test-only продолжает тот же PR. Принятый commit остаётся исходной точкой; последующие изменения только разрешённых тестов не отменяют принятие. Любой production drift блокирует test-only, требует нового анализа и принятия. Test Author не чинит production и не ослабляет тесты.

Подробные raw данные автоматически не публикуются. В shared handoff — имена файлов, pins, результаты assertions без сырых DB rows и ручные сценарии. Локальный подробный отчёт передавать в чат только после проверки секретов/PII.
